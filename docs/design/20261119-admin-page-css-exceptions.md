# 管理端页面级 CSS 三件：受控例外登记结论（后台一期批 4 收口）

- 日期：2026-11-19
- 基线：main `17ad5ba3`（PR #389 合并点）
- 对象：`admin_frontend/src/views/` 下仅有的三件页面级独立 CSS——
  `EmbyAdmin.css`（368 行）、`MetadataSources.css`（651 行）、
  `IdentifyReview.css`（160 行），合计 1,179 行（基线计数，不含本单加的文件头）。

## 背景

后台重设计盘点 P13 指出这三件与全局样式层并行维护；说明书一期批 4 的
处置要求是「收编进统一层或登记为受控例外」。大改造批 C1（#376）已把
三件的字号与颜色归入令牌梯队（分别收口 13 / 23 / 9 处），批 4 主体
（长尾页字面字号与硬编码颜色清零）已完成，但三件本身的处置结论一直
没有落盘。本单补齐结论与自动化登记，不动任何一条样式规则。

## 核查证据（基线实测）

- views/ 下独立 .css 只有这三件，别无其他。
- 三件的 font-size 声明共 43 处，全部为 `var(--ax-fs-*)` 梯队引用，
  字面量 0 处。
- 三件均由各自页面以 `import './X.css'` 引入，是全局（非 scoped）样式表；
  规则挂页面族前缀（`.lib-*` / `.lpm-*` 等、`.ms-*`、`.ir-*`）。

## 结论：登记为受控例外，不收编进全局层

逐件理由：

| 文件 | 保留页面级全局表的理由 |
|---|---|
| EmbyAdmin.css | 下拉面板（`.lib-opt-popper`）teleport 到 body，页面 scoped 样式盖不到（文件内既有注释写明）；且 `.lib-*` 规则被 `components/emby/` 的 LibraryCard / ScanQueueCard 子组件共用，不是本页私有样式 |
| MetadataSources.css | 全挂 `.ms-*` 前缀的全局表，须以特异性压过 SectionCard 的 scoped 样式（`.ms-grid .ms-card > .au-section__body`，文件内既有注释写明） |
| IdentifyReview.css | 与元数据来源页同组同口径（`.ir-*` 前缀），两件成对维护，单独收编一件只会把同组样式劈成两处 |

收编的代价是把 1,179 行页面私有规则搬进全站首屏 CSS，而上面三条
（body teleport、子组件共用、特异性压制）决定了它们本来就必须是
全局表——收编收益低、回归面大，不做。

## 登记后的约束（由守卫自动执行）

登记落在 `scripts/check_frontend_tokens.py` 的
`ADMIN_PAGE_CSS_REGISTERED`（规则 8，本单新增，契约检查 19 → 21 项）：

1. views/ 下页面级 CSS 的集合必须与登记表逐一相等：新增一件未登记、
   或登记的文件被删而登记行没删，检查直接失败。
2. 每件登记文件的文件头必须带「受控例外登记（后台一期批 4）」标记注释。
3. 登记文件的 font-size 只许引 `--ax-fs-*` 梯队，守卫逐行断言。
4. 规则只许挂页面族前缀；要覆写 Element Plus 全局形态走 `styles/`
   主题层，不许借页面级 CSS 扩散全局覆写。

## 复议条件

某页重构后若三条保留理由（body teleport、子组件共用、特异性压制）
全部消失，可再议改为该页 scoped 样式并同步删除登记行；在此之前
登记长期有效，不再逐轮重议。
